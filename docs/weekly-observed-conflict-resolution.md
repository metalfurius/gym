# Observed weekly conflict resolution

New explicit Settings saves capture a verified snapshot of the currently observed conflict/blocked queue IDs for the same account and effective week. OfflineManager.getObservedWeeklyConflictIds(userId, weekKey) requires queueViewVerified and the active owner, returns a fresh array, and uses the immutable payload week, learned canonical conflict week, or original legacy timestamp, in that order. It never uses the current clock as a substitute for an old intent's time.

The optional descriptor.observedWeeklyConflictIds field stores that array in the immutable local intent. queueOperation JSON-copies the descriptor, and the existing intent identity check includes this field. It contains queue IDs, not remote operation IDs. It introduces no semantic dependency and is never included in the Firestore operation payload, preferences document or remote receipt. The durable journal stays at version 3. Legacy descriptors without this field represent an empty observation set and are restored without adding it.

Both direct online Settings saves and replay call OfflineManager.acknowledgeOperation. For a descriptor carrying this field, that method refreshes local durable state, selects only listed IDs still eligible for the same owner/week, and stages their resolved ACKs together with the replacement's accepted ACK. One authoritative journal batch commits all of these ACKs atomically. A conflict learned after capture is left alone. A listed ID that now belongs to another effective week or owner is also left alone; the accepted replacement can finish. Conflicting known canonical weeks for one immutable intent reject through the existing integrity guard.

Resolution criteria remain ephemeral. DurableOutbox.save revalidates owner/week against its own fresh read before preparing the batch, as in the metadata P2 fix. That local validation point does not globally serialize against information learned by another tab later.

If the pre-ACK read or atomic append fails, a new weekly acknowledgement propagates that failure instead of reporting a completed local ACK. The replacement intent and immutable observation list remain durable. A remote applied receipt is idempotent: after a cold reopen, replay may read the same receipt and retry the combined local ACK without applying another weekly revision. An ambiguous append either committed both ACKs or retained both intents; fresh durable state determines which. Advisory refresh/listener failures after a verified batch receipt retain normal committed-success semantics. Other operation types and legacy weekly descriptors retain their existing acknowledgement API.

Future extraction into weekly-preferences-manager must preserve the descriptor field at creation and keep the common acknowledgement path. The typed parity corpus should compare the full descriptor including observedWeeklyConflictIds, queue IDs, immutable operation ID/timestamp, causal predecessors and semantic dependencies. Removing the field would lose offline resolution scope; selecting all current conflicts at acceptance would incorrectly include conflicts the user had not observed.
